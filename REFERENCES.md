# DIRECTION SYSTEM

All directions are defined by SCREEN DIRECTION — where the nose/face points in the FINAL IMAGE as seen by the viewer.
Never by the character's anatomical left/right side.

- FRONT — face or body directed straight at the camera
- NOSE_LEFT — nose/face points toward the LEFT side of the image
- NOSE_RIGHT — nose/face points toward the RIGHT side of the image
- BACK — character is turned with their back to the camera
- UNFIXED — direction not yet confirmed; must NOT be assumed or guessed (reserved for future references; no file in this library is currently UNFIXED)

File names are identifiers only. The Direction field and visually verified image content are authoritative. Never infer direction from a file name.

# REFERENCE SELECTION RULES

All images in this repository represent the SAME AI character.

The character's identity must remain consistent across generations.

Before every image generation:

1. Analyze the requested camera angle, framing and pose.

2. Determine the requested direction using the DIRECTION SYSTEM (screen direction in the final image only).

3. Automatically select the reference set defined in DEFAULT REFERENCE LOGIC for that framing and direction.

4. Do NOT ask the user to manually select references when the appropriate references can be determined automatically.

5. For facial identity, prioritize the FACE REFERENCES.

6. For body proportions and physique, prioritize the FULL BODY REFERENCES.

7. For seated compositions, use the appropriate SEATED REFERENCE together with a suitable FACE REFERENCE.

8. For full-body generations, use the set defined in DEFAULT REFERENCE LOGIC: normally one FACE reference plus one FULL BODY reference; three-quarter full-body generations use one 3/4 FACE reference plus fullbody_3q_front.png plus fullbody_front.png, each with the role stated there.

9. Match reference directions to the requested output whenever a matching-direction reference exists.

10. DIRECTIONAL AUTHORITY: for any three-quarter generation, direction comes ONLY from the matching 3/4 face reference — face_3q.jpg for NOSE_RIGHT, face_3q_opposite.jpg for NOSE_LEFT — and from the prompt. For any side/profile generation, direction comes ONLY from the matching profile face reference — face_profile_left.jpg for NOSE_LEFT, face_profile_right.jpg for NOSE_RIGHT — and from the prompt.

11. Body references used alongside a directional face reference contribute identity, proportions, volume and pose only, and must never override the requested direction. fullbody_3q_front.png (Direction: FRONT) and fullbody_front.png (Direction: FRONT) are never direction sources in three-quarter or side-view generations.

12. Never mirror or flip any reference image, and never mirror an identity or body reference to manufacture the opposite direction. Where no matching-direction body reference exists, use only the substitute defined in DEFAULT REFERENCE LOGIC, for proportions only, and state the required direction in the prompt.

13. fullbody_profile_right.png is Direction: NOSE_LEFT. Never use it in any NOSE_RIGHT generation, as a directional reference or otherwise.

14. File names never determine direction. Use only the Direction field of each entry.

15. Never assume a direction for any file marked UNFIXED.

16. If the requested angle falls between available references, select the closest matching references.

17. Multiple references may be used when supported by the generation model.

18. Use the RAW URLs listed in this document as image inputs when calling Replicate.

19. Never require the user to manually copy GitHub URLs for normal generations.

20. Preserve facial identity, recognizable facial geometry, body proportions and overall character consistency.

21. Clothing, environment, lighting, pose, camera, expression and styling may change according to the user's request unless explicitly locked.

22. Do not treat clothing or backgrounds visible in reference images as part of the character's permanent identity.
